| DEV-1697 | 🐞 **BUG — `?scope=subtree` on the structure act-log routes leaks every other structure's audit rows when the resolved subtree is empty.** `CustodyStore.ListActs`/`.CountActsByClass` (`custody_impl.go`) only add a `chapter_id IN (?)` filter `if len(structures) > 0` — when a caller-supplied `ScopeResolver.Subtree` legitimately answers "no descendants" with an empty, non-nil, no-error slice (a plausible real answer for a leaf structure, or for an id a resolver treats as "found nothing" rather than an error), `actLogScope` (`routes/custody.go`) passes that empty slice straight through, the `len(structures) > 0` guard is false, no `WHERE` clause is added at all, and the query returns/counts **every structure's** act-log rows, not zero. Demonstrated through the real `routes.CustodyRoutes` mux (sqlite, in-process) with a resolver stub answering `Subtree(ctx, id) → ([]string{}, nil)` for every id: seeded one act on `structure-A` and one on `structure-B-SECRET`; `GET /structures/structure-A/act-log?scope=subtree` returns **both** entries (`entry_count=2`), including `structure-B-SECRET`'s, whose id was never in scope; `GET /structures/structure-A/act-log/counts?scope=subtree` reports `everything=2` for the same reason. This is a cross-structure audit-log data leak in exactly the system meant to be trustworthy about who-did-what-to-whom — the empty-scope case should return/count zero, the same way an ordinary `WHERE chapter_id IN ()` would if the driver supported it directly. **Fix location**: `custody_impl.go`'s `ListActs`/`CountActsByClass` — distinguish "no scope filter requested" (`structures == nil`, used today by `listCustodyEvents`/`countCustodyEvents`'s org-wide callers, which never pass a `structures` argument at all) from "scope resolved to nothing" (`structures != nil && len(structures) == 0`, which should filter to zero rows) — e.g. `if structures != nil { q = q.Where("chapter_id IN ?", structures) }`, matching Go's own nil-vs-empty-slice distinction; `actLogScope` already returns `[]string{structureID}` (never nil) for the default `scope=structure` case, so this fix does not touch that path. Pinning test: `routes/custody_scope_test.go`'s `TestListStructureActs_EmptySubtreeScopeLeaksOtherStructures` (real mux, sqlite; currently green, asserting the *broken* leaking behavior on both `/act-log` and `/act-log/counts` — will fail once the fix lands, per the test's own comment). | 📋 Not Started | — |
